# TianShouDSSAT 待开发内容与研究续接清单

## 1. 当前项目状态

当前仓库已经完成了第一阶段基础改造的主体骨架，具备以下能力：

- DSSAT 接入层、任务定义层、评估层、实验装配层已经初步解耦
- `TaskEnv` 已成为统一训练与评估链路的主入口
- observation / action / reward 已具备可插拔 schema 结构
- baseline actor 与 RL actor 已可复用统一 evaluator 协议
- episode 级 KPI 与 benchmark 结果导出链路已经具备初版能力

这意味着项目已经跨过“原型能不能跑”的阶段，进入“如何把实验体系做扎实、做可复现、做成可汇报 benchmark”的阶段。

## 2. 待开发内容总表

### A. 最高优先级：把实验协议做成真正可复现

1. 完善 train / validation / test 的协议固化
   - 固定天气文件切分与记录方式
   - 固定多 seed 实验模板
   - 固定 baseline 对照集合
   - 固定训练后统一评估入口

2. 继续补齐 benchmark 结果导出层
   - 增加跨 run leaderboard 视图
   - 增加 best run / best actor 摘要
   - 增加均值、标准差、stderr、置信区间等统计字段
   - 让导出产物可以直接进入 notebook、论文表格与汇报 PPT

3. 建立稳定的实验批次管理方式
   - 统一 run 命名规则
   - 固定产物目录规范
   - 固定 manifest 字段
   - 让同一批实验能够自动形成横向对比索引

### B. 高优先级：清理影响复现性的工程脆弱点

1. 清理绝对路径依赖
   - 移除硬编码项目路径与 DSSAT 路径
   - 把资源解析统一收敛到 resolver 层

2. 收敛运行时补丁逻辑
   - 逐步替换 `fix_dssat_pdi.py` 这类字符串改写式补丁
   - 减少 crop-specific monkey patch
   - 降低 vendored 目录与上层研究逻辑的隐式耦合

3. 提升跨机器可迁移性
   - 梳理虚拟环境与运行依赖
   - 固化关键运行前检查
   - 让新机器能够用更少手工操作复现训练与评估

### C. 高优先级：把“农业任务定义”继续做深

1. 奖励函数研究化
   - 从当前 yield / cost 框架继续扩展到多目标权衡
   - 加入环境代价与稳健性视角
   - 对接潜在奖励塑形研究路线

2. 观测设计继续增强
   - 增加更稳定的资源预算状态
   - 增加更清晰的管理历史摘要
   - 评估 forecast-aware observation 对策略稳定性的作用

3. 动作空间继续农业化
   - 继续评估阶段约束与预算约束
   - 增加 action masking 或禁行动作机制
   - 为未来参数化动作空间保留接口

### D. 中优先级：把“可信结论”所需测试补齐

1. 增加农艺正确性测试
   - 施肥增加时累计施氮是否单调增加
   - 灌溉动作是否真实影响总灌溉与水分相关变量
   - episode 汇总指标是否可复算

2. 增加实验协议测试
   - weather split 是否稳定且无重叠
   - 多 seed 汇总是否稳定
   - baseline 排名与 KPI 导出是否符合预期

3. 增加复现性测试
   - 同 seed 是否可复现
   - 不同 seed 是否保留合理方差
   - benchmark 产物是否完整落盘

### E. 中优先级：推进算法与研究问题本身

1. 继续推进 reward shaping 方向
   - 用 LAI / biomass 增量设计更系统的 shaping 方案
   - 比较 sparse terminal reward 与 shaping reward 的收敛差异

2. 推进风险敏感 RL
   - 评估 QR-DQN / CVaR 类方法
   - 强化极端气候下的左尾表现分析

3. 推进跨天气年稳健性实验
   - 将 domain randomization 与跨年验证并入标准 benchmark
   - 建立异常气候压力测试子协议

### F. 中优先级：作物支持与环境诊断

1. 继续验证 wheat 任务配置稳定性
2. 排查 tomato 初始化阻塞与对齐问题
3. 梳理作物支持矩阵与每种作物的任务边界

## 3. 建议的下一阶段执行顺序

建议按以下顺序推进：

1. 先把 benchmark 导出与实验协议完全固化
2. 再清理绝对路径、补丁与环境脆弱点
3. 随后补齐农艺正确性测试与复现性测试
4. 最后进入 reward shaping、风险敏感 RL 与跨气候稳健性研究

这个顺序的原因是：

- 没有稳定实验协议，后续任何算法收益都难以证明
- 没有可靠导出与批次管理，实验会很快失去可追踪性
- 没有环境稳定性与测试托底，研究结论会被工程噪声污染

## 4. 推荐形成的阶段性交付物

建议后续每一轮开发都至少产出以下四类成果：

- 代码变更
- 对应测试
- benchmark 产物样例
- 一页式实验结论摘要

## 5. 当前项目暂存建议

本次建议将当前仓库作为“Phase 1 基础建设快照”进行保存，后续开发研究都基于这个快照继续推进。其定位不是“最终稳定版”，而是：

- 一个已具备统一任务装配能力的研究底座
- 一个已具备初步 benchmark 导出能力的实验仓库
- 一个适合继续推进可复现农业 RL 研究的中间里程碑
