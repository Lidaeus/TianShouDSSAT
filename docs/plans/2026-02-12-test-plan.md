# 环境健壮性与多作物适配测试方案 (2026-02-12)

## 1. 测试目标
确保重构后的 `DssatPdi` 和 `DssatGenericWrapper` 在 Tianshou 2.0 框架下运行稳定，支持多作物并行切换，且物理引擎资源注入正确。

## 2. 测试用例矩阵 (Test Matrix)

### TC-1: 核心 API 合规性测试 (Gymnasium Compliance)
- **目的**: 验证返回值数量和类型。
- **动作**: 调用 `reset()` 和 `step()`。
- **预期**: `reset` 返回 `(obs, info)`；`step` 返回 `(obs, reward, terminated, truncated, info)`。

### TC-2: 多作物切换稳定性 (Multi-Crop Isolation)
- **目的**: 验证番茄和玉米在同一个进程中轮流启动是否干扰。
- **动作**: 顺序实例化 Maize -> close -> Tomato -> close。
- **预期**: 两者均能成功 reset 并获取正确的生理特征（如番茄有 `xlai`，玉米有 `istage`）。

### TC-3: 资源自动注入验证 (Resource Auto-Injection)
- **目的**: 验证 Wrapper 是否自动补全了 .WTH 和 .CLI 路径。
- **动作**: 在不显式传入 `auxiliary_file_paths` 的情况下启动番茄。
- **预期**: 物理引擎不报 `MAKEFW` 错误，顺利运行。

### TC-4: 历史状态拼接验证 (History Buffer Stability)
- **目的**: 验证 `history_len > 1` 时的数据对齐。
- **动作**: 运行 5 个 step，检查 obs 维度。
- **预期**: obs 维度 = `num_keys * history_len`。

### TC-5: 极端动作健壮性 (Robustness)
- **目的**: 验证传入异常 action 值时的处理。
- **动作**: 传入极大的灌溉量或施肥量。
- **预期**: `DssatPdi` 应能安全截断动作而不崩溃。

## 3. 测试实现计划
使用 `pytest` 框架编写自动化测试脚本 `tests/test_suite_v2.py`。
